## 🔹 Positioning Recommendation

Lead with one sentence, every time: **"Backend engineer — Go and Python, Kubernetes controllers for a globally distributed API gateway at 100k+ requests/day, with production AI-system evaluation experience."** This run's evidence makes the case: the two roles that match best (**NVIDIA #1**, **MongoDB #4/#7**) both ask for exactly that combination, and the three strongest Israeli roles all name Go or Python as an accepted primary language.

Three specific adjustments for this set of openings:

* **Put Kubernetes-controller work first, not the API gateway.** Four of this run's new reqs — NVIDIA, Stigg, MongoDB Atlas Clusters, Appdome — treat Kubernetes as a mandatory rather than a nice-to-have. "I write Kubernetes controllers in Go" is a scarcer claim in this market than "I build backend services," and it is the one that reaches the #1 role.
* **Promote root-cause analysis from a soft skill to a technical credential.** It is written as an explicit requirement in **five** rows this run: Zafran ("trace data end-to-end... from API response parsing through failure handling and edge case reasoning"), Riverbed ("a knack for figuring out why things break"), GitLab ("investigate technical problems... work toward a practical resolution"), GovEagle ("debugged real production problems and can talk concretely about what broke"), and Twine ("debug technical problems methodically"). Have two concrete, specific production-debugging stories ready with the mechanism and the fix, not the outcome.
* **Lead with AI *evaluation*, not AI *interest*.** Nine of this run's new reqs touch LLMs, agents or RAG, and almost every applicant will claim enthusiasm. "I evaluate and improve generative-AI systems in production" plus the Qualtrics classification and summarization work is a measurable claim where most of the pool has only a hobby project.

**What to de-emphasize.** Freelance teaching years — keep them as evidence of communication and mentoring, never adjacent to the experience count, and never in a way that lets a screener read 2–3 years as something else. Academic machine-learning and data-science research — it draws fire toward ML-engineer and data-science roles that are explicitly off-target, and in Israel it invites the "needs a PhD" algorithm-research track. The breadth of the skills list — Java and C# on a résumé invite questions the candidate cannot answer with production evidence, and they dilute the Go/Python/Kubernetes signal that is doing the actual work. Frontend depth — React and TypeScript should appear as proof of full-stack range behind backend ownership, not as a headline, or the full-stack reqs will route the candidate to the UI half.

### Method note — what "verified" means in this report

Every row in the table was retrieved in this run. Nothing was recalled, pattern-matched, or reconstructed, and no posting URL was constructed without being fetched. Specifically, each row rests on at least one of:

* a **Greenhouse board API** call (`boards-api.greenhouse.io/v1/boards/{token}/jobs/{id}`) returning an open req with its `updated_at`;
* an **Ashby posting-API** call (`api.ashbyhq.com/posting-api/job-board/{org}`) showing the posting with `isListed: true` and its `publishedAt`;
* a **SmartRecruiters API** call (`api.smartrecruiters.com/v1/companies/CheckPointSoftwareTechnologies2/postings/{id}`) with its `releasedDate`;
* a **Comeet `POSITION_DATA`** read off the employer's own ATS-hosted page, carrying the live `time_updated` stamp;
* a **Workday CXS** call against the employer's tenant;
* a **devjobs.co.il detail-page fetch** carrying the full requirement text, the required-years badge, the work model and an update date;
* a structured **Indeed connector** record (`search_jobs` → `get_job_details`).

Every public link printed above was additionally fetched this run and confirmed to return **HTTP 200** (13 of 13). The one row with a verification caveat — **NVIDIA #1** — says so in its own cell, names what is missing, and quantifies the conflict with NVIDIA's own careers site rather than smoothing it over. Two prior Google rows that could not be re-verified were dropped rather than carried.
